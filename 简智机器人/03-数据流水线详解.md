# 03 · 数据流水线详解:采集→清洗→标注→质检→交付

> 充分理解"数据是生产出来的"这条流水线 · 每个环节讲清:目标 / 输入输出 / 具体步骤 / 参与角色 / 难点 / 质量指标 / 你的经验连接点

---

## 全景图

```
客户需求(场景+技能+数据量+规格)
   ↓ 拆解成采集方案
① 采集(场景搭建+数采员穿戴DAS作业) → 原始多模态数据流
② 清洗/预处理(同步、去废、标准化) → 干净的原始数据
③ 标注/真值生成(DFM自动+人工校验) → 带标准答案的训练数据
④ 质检(标准+抽检/全检+返工闭环) → 达标数据
⑤ 交付(按SLA打包交付客户) → 客户模型训练
   ↓ 真机评测效果回流 → 反馈下一轮采集(数据飞轮)
```

---

## ① 采集:数据是"演"出来的

**目标**:按客户要的场景/技能,批量生产高保真的人类操作数据。

**输入**:采集需求单(什么场景、什么技能、多少小时、什么规格)
**输出**:原始多模态数据流——第一人称视频、深度信息、手部/全身轨迹、6D 位姿、触觉/力觉信号、声音

**具体怎么干**:
1. **场景搭建**:按需求还原真实环境——家居、商超、工业装配、仓储物流、医疗辅助等(简智已覆盖 1 万+ 处真实场景)。物品摆放、光线、动线都有规范
2. **数采员作业**:穿戴 DAS Ego(头显视角)+ Fingers/Gripper(手部),按**动作脚本**反复执行:抓取零件、开关设备、分拣物料、整理货架……每个动作既要"自然"又要"可复现"
3. **技术保障**:1ms 级头/手/眼时间同步;设备佩戴检查;每批次开始前的设备校准
4. **现场管理**:数采员排班、单日采集时长、中途质量抽看(现场 QC)、废批次当场标记

**难点**:
- 场景还原度不够 → 数据失真,客户模型学坏
- 动作覆盖不足 → 只采了 20 种抓法,客户要 50 种
- 设备故障/同步漂移 → 整批报废
- 数采员疲劳/动作变形 → 后段数据质量下滑

**质量指标(面试可讲)**:时间同步精度、轨迹完整率、场景还原核验、单批次报废率

**你的连接点**:迪士尼数据服务中台=把多来源数据按统一规范生产出来;现场管理≈你带过 20+ 人团队的多站点协调。

---

## ② 清洗/预处理:从毛坯到净料

**目标**:把原始数据变成"干净、对齐、标准化"的可加工状态。

**具体步骤**:
1. **多传感器时间轴同步**:头/手/眼/触觉信号对齐(平台自动,1ms 级)
2. **废数据剔除**:采集失败、剧烈抖动、遮挡、传感器丢帧的批次自动+人工筛除
3. **格式标准化**:统一数据结构、命名、元数据(场景 ID、技能 ID、设备 ID、操作员 ID 可追溯)
4. **入池**:进入 GenADP 产线待加工

**难点**:周产 10 万小时的量,**废品率高 1 个点,成本就是几十上百万级**——所以废品率控制要在采集端就做(现场 QC 前置),不能全靠后端清洗兜底。

**你的连接点**:数据中台的数据清洗与标准化;成本管控(废品率=直接成本)。

---

## ③ 标注/真值生成:给数据写"标准答案"

**目标**:让每条数据带上"正确答案",模型训练就是对着答案学。

**标注什么**:
- **6D 位姿**(物体三维位置+三维朝向)
- **手部关键点/手部跟踪**
- **动作分段**(这段是"抓起"→"移动"→"放下")
- **任务语义**("把杯子从桌上拿到架子上")
- **思维链 CoT**(完成任务的推理过程描述)
- **触觉对齐**(力的信号与动作对应)

**简智的特殊性:DFM 自动生成大部分真值,人工做校验兜底**。这不是纯人肉标注公司——人机分工是它效率的核心。

**具体分工**:
| 环节 | 谁 | 说明 |
|---|---|---|
| 真值自动生成 | DFM 模型 | 位姿/跟踪/分段自动算 |
| 自动结果校验 | 人工质检员 | 抽检自动生成的真值准不准 |
| 边界案例判定 | 人工 | 遮挡、模糊、多解动作——规则写不出来的 |
| 规范维护 | 交付经理/标准组 | 标注规范、边界案例判例库持续更新 |

**难点**:规范要细到"边界案例怎么判"——比如"手有没有真正握住杯柄",两个标注员判得不一样,数据就没法用。**规范一致性 > 单点准确率**。

**你的连接点**:迪士尼报表口径统一(4 业务线数据模块化=同一个"标注规范"问题);讯联运营机制标准化=把个人经验变成全团队规范。

---

## ④ 质检:数据出厂前的闸门

**目标**:交付的数据达标——质量是简智的产品口碑,质检标准本身就是产品。

**三级质检设计(面试可以直接讲这个框架)**:
1. **自检**:数采员/标注员交前自查(清单制)
2. **互检/过程检**:现场 QC 抽看、批次内交叉校验
3. **专检**:质检组按标准抽检/全检——关键项全检(如时间同步、轨迹完整性),一般项抽检(如语义标注,按 AQL 抽样)

**质检查什么**:
- 标注准确率(真值对不对)
- 轨迹完整性(动作有没有断)
- 一致性(不同标注员对同类数据判得是否一致)
- 规格符合性(时长、格式、元数据齐不齐)

**不合格处理闭环**:标记 → 定位原因(采集问题?标注问题?设备问题?)→ 返工或报废 → **原因归类进复盘**,同类问题进 SOP 防再犯。

**你的连接点**:同盾金融风控项目的质量与合规管控(监管级质量要求);你熟的"检验标准+异常闭环"完全同构。

---

## ⑤ 交付:按 SLA 兑现给客户

**目标**:按客户要求的规格、数量、时间,稳定交付。

**交付内容**:标准化数据包(数据+真值+元数据+质检报告)
**交付节奏**:按里程碑分批交付(先样批→客户确认规格→再批量)
**SLA 三要素**:数据量(小时/条数)、质量(准确率/合格率阈值)、时间(交付节点)

**关键机制——样批确认**:大批量生产前先交小样批,客户确认"这个规格对不对",避免整批返工。这是数据交付和软件交付相通的"最小可行交付"思路。

**你的连接点**:这是你 7 年的老本行——里程碑、SLA、验收、客户沟通。**你最强的环节恰恰在这里**,面试要传递"交付端我是老手,生产端我快速补"。

---

## ⑥ 闭环:真机评测回流(数据飞轮)

客户拿数据训好模型 → 真机实测 → 泛化差的场景暴露 → 反馈简智 → 下一轮采集补这些场景。**交付经理的闭环意识**:交付后主动跟踪客户评测反馈,把"泛化失败"翻译成"下一批的采集需求"。

---

## 七、整条流水线的 KPI 体系(面试讲体系就用这张表)

| 层 | 指标 | 说明 |
|---|---|---|
| 产能 | 周产小时数、单场景日产能、设备利用率 | GenADP 节拍:采集后 2 小时出成品 |
| 质量 | 批次报废率、真值准确率、规范一致性、一次交付通过率 | 一次通过率是最能体现体系水平的指标 |
| 交付 | SLA 达成率、按时交付率、样批一次确认率 | 客户视角 |
| 成本 | 单小时数据成本、返工率、设备故障停机率 | 流程标准化的直接收益 |
| 团队 | 人效(小时/人/日)、培训达标周期 | SOP 成熟度体现 |

---

## 八、面试一句话总结

> "这条流水线的本质是**把'人类技能'做成标准化量产的产品**:采集是生产、标注是精加工、质检是出厂检验、交付是履约,真机回流是售后反馈。我在迪士尼和讯联做的就是同类的事——把多来源、非标的生产过程,变成规范、可控、可复制的体系,所以我接这套逻辑不需要从零学,只需要把行业术语和场景手感补上。"
